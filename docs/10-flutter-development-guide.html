02

围绕一个完整的工作人员目标

产品目标：工作人员无需开发者在场，即可把已经确定的用药安排落实到药盒，处理中断和异常，并查清实际发生过什么。系统不承担诊断或自动开处方。

维护资料与处方长者身份、药品、剂量、餐食要求及疗程。

领取并识别药盒确定本机归属，开仓后核验所属长者。
逐药摆放主动开始本药，自动定位和计数。

查询与导出查询计划、机器反馈、人工处理和标签 PDF。

以 Android 横屏平板为首发重点，同时验证竖屏、分屏、软键盘和大字体。当前沿用用户确认的唯一极简风格继续完善功能；左上角保留 Pillxai 字标与简约黑色图标。布局按可用宽度调整，不通过设备名称判断“平板模式”，具体尺寸仍需在目标设备验证。Flutter 官方建议基于窗口空间和输入方式构建自适应布局，见 自适应实践。

正常执行页沿用第 03 节确认的极简风格：当前长者、药物和进度清楚可见，暂停直接可达，开口调整一步展开。下一药弱化预告；计划明细、机构与设备详情、同步诊断按需查看。异常影响身份、数量或能否继续时，立即展开必要提示与处理动作。

交互质量要求

  • 主要触控目标至少按约 48 个逻辑像素设计，并在真实平板验证误触；关键按钮使用动作名称，如“开始本药”“暂停”“确认跳过，记为未完成”。
  • 横屏可显示列表与详情，窄屏改为逐层页面；表格保留必要列，详细字段进入详情，不把整张桌面表格等比例缩小。
  • 支持系统字体放大、键盘导航、屏幕阅读器标签；错误与成功同时提供文字，不只依靠颜色或动效。
  • 每个查询都有加载、空结果、失败、成功状态；失败不能显示“0 人待摆”。保存失败保留输入，重复点击由业务防重处理。
  • 切页、旋转屏幕、页面重建不重置任务；切换其他应用和锁屏时摆药继续，这是首发验收要求。主动关闭软件则进入停止并取消流程，区别于普通切后台。
  • 执行状态以本机事件立即更新；中央刷新和大导出在旁路进行。网络失败不能阻塞本机暂停等操作。
05

三个清楚的责任边界

采用 Flutter 客户端和 Python + FastAPI 中央服务，中央先按模块化单体组织。终端执行核心独立于页面；共享执行逻辑优先考虑 Dart。Android 用 connectedDevice 类型的前台服务承载持续蓝牙执行及必要的平台生命周期协作，具体 Dart/原生边界在真机探针中验证；Dart isolate 本身不等于系统后台服务。

Flutter 界面与展示状态

资料输入、计划核对、执行入口、记录和设置。页面读取业务结果与执行快照，发出语义操作。

Python + FastAPI 中央业务

权限、长者与处方、计划计算、任务归属、记录、参数版本、导出和发布信息。

本机执行核心

每机独立会话、命令顺序、状态转换、原始事件、本地事务和待同步队列。

本机适配器 → 真实设备 / 模拟设备

处理蓝牙或串口连接、协议编码、反馈解析。核心只调用“开始批次、暂停、恢复、开仓”等语义操作；模拟器走同一接口。

边界由拥有的事实决定

中央决定任务属于哪台机器、依据哪版处方；本机记录物理执行发生了什么；界面展示事实并收集操作。客户端不直接访问中央数据库，中央不把网络请求重试转化为再次出药。

精简从减少重复开始

计划只在中央算一份；离线执行冻结快照。本机用一个顺序命令入口处理当前设备。公开模型从同一契约生成，页面不另写一套业务计算或状态机。

后端已确定为 Python + FastAPI

用户已明确选择 FastAPI。使用 Pydantic 声明公开模型并导出 OpenAPI 契约，验证 Dart 客户端生成链。

处方剂量、计划计算、任务归属与设备动作依据确定规则运行。FastAPI 负责中央业务 HTTP 入口，Android 执行模块负责本机实际动作；公网网络不进入每次设备指令的必要路径。

位置建议起点选择理由与验证条件
前端Flutter + Dart；展示、业务状态、本机执行分开。复用界面和类型；检查目标平台插件。路由和状态管理只选一套，在首个流程验证后锁定。
中央服务Python + FastAPI + Pydantic，模块化单体。接口与校验可读、公开 Schema 可导出；类型生成与校验共享权威模型，保持服务结构精简。
中央存储PostgreSQL；SQLAlchemy 与 Alembic 为候选。事务、并发约束、历史查询；用真实数据库测领取冲突和迁移，不以 SQLite 替代这部分集成测试。
终端存储SQLite；选一个可迁移、可事务测试的 Dart 访问层。任务快照、事件和待传项可原子落盘；测试崩溃、磁盘失败与恢复，不只验证写入成功。
通信与作业HTTP API 起步；大导出使用可查询状态的后台作业。同院状态刷新先用可测的简单方式；有实测需求再引入推送、独立 worker、缓存或消息中间件。
依赖与工具锁定实际版本与生成器；优先使用现有工具和项目内环境。新增依赖需解释收益、平台覆盖、许可和替代成本；不在本指南中凭空锁定未验证版本。
06

让计划、数量和历史都能解释

处方 · 需要什么

长者的药物条目、剂量、时段、餐食关系和有效期。修改产生版本，条目身份稳定。

计划 · 本次安排什么

具体日期、药物、颗粒、盘用途和位置；保存所依据的处方、设置及设备能力版本。

结果 · 实际发生什么

执行状态必须经得起切页、断网和重启

由本机执行核心维护任务、批次、命令意图和可用操作。界面订阅快照；切页和状态重建仅重新展示。建议分别建模执行阶段、连接状态、结果、取盒状态、同步状态，避免把五件事压成一个“已完成”布尔值。

阶段允许推进的依据必须防止的错误
预览 / 已领取联网取得有效归属；计划版本有效；开仓放盒并识别长者。重复领取、忽略冲突、掉线后把未开始任务当成可离线启动。
准备启动中央记录启动许可；本地保存完整快照、所需资料与启动意图，全部完成后才发首个摆药命令。本地未保存先动作；网络超时后把可能已启动的任务释放给另一机器。
执行中当前药物参数 → 数量矩阵；按本机反馈更新累计数，等待明确完成反馈。以 100% 代替 FINISH；页面刷新重复发送矩阵；将命令写入当成机械到位。
暂停 / 恢复请求与确认分开；保留原进度，按既有恢复操作继续。恢复时从头下发参数和矩阵；暂停未确认就宣称已停稳。
药物退出 / 换药跳过需等待停转 ACK、退出 ACK/DONE；下一药由人员开始。尚未确认退出就开仓或进入下一药；把跳过写成完成。
换盘 / 取盒盘用途与长者持续可见；实际取盒后收轨道，保存确认来源。开仓即算取出；缓存无卡即算无盒；整项结果被换盘或收仓失败覆盖。
中断 / 待核实保留最后已知状态；按现场核对决定恢复、人工结果或结束。重启或重连自动重发完整矩阵，或者用未知数填零。

首次识别的推进条件：摄像头与 RFID 的有效观察分别保存；一个来源不可用或未绑定，不抹掉另一个有效匹配。两个有效来源指向不同长者时禁止开始。首次开始前持续观察，换盒或全部有效标识消失应撤销核验。真实模式没有人工指定长者来冒充识别成功的入口。

本地保存与补传的最小可靠流程

  1. 推进执行前先落盘命令意图与当前状态；保存失败则不开始新批次、不恢复投料、不发新矩阵。已有设备能力中的暂停/停转入口仍保持可用，并显示请求结果与现场处理提示；无法完整落盘的事实明确标为记录异常。
  2. 收到事件后，在一个本地事务中保存原始事实、更新执行快照、追加同一事实的待上传项；原始数据与去重判定分开。
  3. 上传携带稳定事件身份。中央事务验证机构、任务与设备归属，并去重写入，返回确认；本地收到确认后才标记已同步。
  4. 确认丢失时可重传同一事实；补传不会发送机器命令。任务关闭后迟到事件保持明确关联，不串到下一药。

数据库事务不能覆盖外部机器动作。程序可能在命令发出后、确认写入前崩溃；这类“不知道是否已执行”的情况进入现场核对。协议没有批次身份时，不承诺物理动作的“恰好一次”。

中断按真实原因处理

情况规定行为
仅中央网络断开设备连接正常时，完成已开始任务内所有药、换盘和人工处理，持续本地保存；新任务等待联网。
设备连接断开显示执行中断。重连仅连接原设备；确认未断电/复位、原药盒与药物和进度仍保留后，人员主动恢复，不重新发送矩阵。
应用重启 / 设备复位恢复未结束任务，显示最后已知阶段；未知批次先核对。已处理批次不重摆，剩余从未启动批次在原机器恢复就绪后继续。
平板锁屏 / 切其他应用按用户要求继续当前摆药，Android 前台服务维持执行与蓝牙处理。回前台恢复订阅并检查原会话；有效会话直接展示，不重复连接或发送矩阵。目标机型上的锁屏、省电与持续运行必须通过实测。
主动关闭软件停止安排后续动作，持久化取消意图并执行停止/取消流程；本次不计完成，已同步的本次覆盖随取消失效，断网时保留取消待同步。只有设备停止反馈或明确现场核对后才显示已停稳。普通取消是否彻底删除记录尚待明确，先保留核对证据，不能自动套用“结束不记录”的删除入口。
系统强杀 / 崩溃 / 断电进程可能没有任何退出回调，无法保证下发最后停机命令。下次进入显示异常中断并核对，不自动继续或认定完成；机械是否停下必须由已验证设备能力保证。

已经确认的删除例外：设备中断或异常核对时，可显式选择“结束此次分药（不记录）”。人员先确认机器停稳、药盒与药物处理妥当；软件持久化删除意图并关闭连接，再删除中央任务、结果、反馈及关联审计，最后删除本机快照、待传项和该任务诊断。该操作不发送机器命令，不产生覆盖，不保留中止记录，也不提供已结束历史任务的通用删除入口。失败或重启继续停留删除阶段，直到重试完成；期间不能恢复或新开任务。

实现删除与同步时必须验证并发补传和迟到事件：事件接收只能归入现存有效任务，不能自行创建任务；本机删除阶段关闭接收和上传入口。不得为防重又永久保留本应删除的任务反馈或诊断副本。

换盘与取盒已收敛为同一规则

换盘：清除上一盘识别结果，下一盘重新识别通过后才允许“已换好，继续摆药”；失败、冲突或其他长者药盒均不得继续。确认后启动下一药，不重复增加一次开始操作。

取盒：系统取得本次新鲜、稳定的取盒观察后自动收回轨道；检测失败提供重试及人工确认入口。保留自动或人工确认来源，断开连接不等于药盒已取出，收仓发送成功不等于机械已到位。

验证 Android 直连与持续执行

现有设备为 STM32 + HC-06 经典蓝牙串口，波特率 115200。首发 Android 平板直接连接 HC-06，一台终端固定对应一台机器。已确认的正常流程、报文与反馈以 04 为依据，新适配器独立编写。既有串口测试不能证明新版 Flutter 或 Android 已通过实际设备验收。

目标可以采用的验证路径不能跳过的条件
Android 平板 · 首发采用经典蓝牙 RFCOMM/SPP 路径直连 HC-06。用原生适配或明确支持此能力的 Flutter 插件。真实机型上的配对、扫描/连接权限、连续读写、掉线、后台、锁屏和退出。BLE 插件不能仅凭名称视为支持 HC-06。
iPad / iPhone核实实际配件和可用协议；必要时评估经确认的 BLE、网络网关或兼容配件方案。Core Bluetooth 的 GATT / BR/EDR 支持不等于通用 HC-06 SPP 可直接使用；不能承诺一个插件解决全部问题。
Windows验证已配对 HC-06 的出站 COM 连接、端口释放与重新打开。不能把 Windows COM 实现直接复用为移动端传输；安装、退出、更新单独验证。

技术依据：Android 蓝牙连接、蓝牙权限、Apple Core Bluetooth、Apple 对 GATT over BR/EDR 的说明、External Accessory。这些是系统 API 能力说明，不能替代本设备实测。

把协议细节限制在一个适配边界

  • 语义接口表达连接、开仓、识别观察、开始批次、暂停、恢复、退出本药、清药、复位、设置开口和收轨道；页面不出现报文字节。
  • 每台设备独立会话，按命令顺序处理 ACK、DONE、FINISH；没有设备任务编号时保存关联质量与未知情况，不能伪造硬件已回传的批次身份。
  • 协议适配处理分段输入、粘连、空行、异常数值、重复、乱序及迟到消息；不在界面回调里修改处方或覆盖。
  • 矩阵的字节可表达范围和真实药格容量分开。第四行和左右方向经位置测试确认；业务日期和物理行列不混为一组编号。
  • 真实适配器与模拟器共用语义入口；模拟事件始终带演练标记，不能混入实际覆盖和统计。

已确认的正常命令顺序

开仓放盒 → 自动核验长者 → 保存启动 → 本药转盘/舵机参数 → 本药矩阵 → 累计反馈及完成 → 下一药或开仓换盘 → 实际取盒 → 收轨道。首次矩阵前不额外关仓；暂停恢复不重发矩阵；换盘须重新识别通过，确认后不再重复要求一次开始操作。

异常跳过按“停转并等 ACK → 退出本药并等 ACK、DONE → 才能进入下一药或开仓”。等待超时进入可解释的核对状态，不用固定延迟猜测机械动作已经完成。

舵机调节沿用 04 / P07 的 0–1 设备刻度、0.01 步长；数值越小开口越大。连续拖动只保留最新待发值，约 400 ms 防抖，结束操作可立即提交；初次显示、重连和页面重建不自动发送初值。批次改变时取消旧待发调整。

首阶段就做硬件可行性验证。先测目标平板上的连接、读写、前后台与恢复，再扩展完整界面。如果需要保留现场电脑或增加网关，它会改变终端归属和使用方式，应先由用户确认；不能在后期把这一变化当成普通实现细节。

后台继续与关闭停机是两套路径

Android 执行任务从可见界面启动 connectedDevice 前台服务，保留运行通知并持续保存事实。前台服务本身不保证 CPU 一直运行；按实际执行阶段评估有界 partial wake lock，任务结束即释放，见 Android 保持唤醒说明。不能依靠屏幕常亮完成锁屏验收。

应用内“停止并退出”可执行停机握手。最近任务划走可接入 onTaskRemoved，但需真机验证，不能把 stopWithTask 属性当成已发送停机。Android 的 活动应用 / Task Manager 停止会结束应用且不发回调；强行停止、崩溃、断电也不能保证最终命令。HC-06 失联时机器如何停止，仍需实际设备事实。

iPad / iPhone 属于后续阶段，其实际构建、签名与真机测试需要 macOS、Xcode 和 Apple 签名配置。当前 Windows 主机不能代替该验证，见 Flutter iOS 开发设置。

新参数初值与学习策略基于本次实测设计，不继承旧公式或旧参数经验；配置允许打开学习不等于公式已经可用于生产。原始脉宽保存原值与质量，单位未经确认不换算；样本不足、异常或版本过时不生成新的有效学习结果。

模块公开职责数据约束
身份与机构登录、账号状态、机构成员关系和权限。机构范围由服务端授权决定；客户端提交的机构 ID 只是请求条件。

跨语言数据约定

  • 身份：稳定 ID 使用字符串；长者显示编号、床位、RFID UID 和内部 ID 各自独立。UID 保留前导零及原始文本。
  • 时间：业务日期用明确日期类型；事件时刻保存带时区的时间及接收来源。服务端与客户端不能各自按设备时区解释覆盖。
  • 数量：原片剂量在 API 中用精确十进制字符串或经确认的固定精度单位；机器颗粒是整数。Python 使用 Decimal 等精确表达，Dart 不用二进制浮点做剂量边界判断。
  • 版本：处方、设置、计划和参数各有版本；更新使用预期版本，明确返回冲突。空值、零、未提供字段分别定义。
  • 错误：公开稳定错误码、可理解信息和必要字段定位；区分校验、权限、版本冲突、占用、设备中断及服务器不可用。
  • 兼容：客户端遇未知执行状态不能放开动作。新增字段、枚举和旧客户端的处理方式必须在契约样例中验证。

存储以可恢复的事实链组织

中央保存机构、长者、处方版本、计划快照、任务归属、批次结果、参数历史、采样及附件关系。本地保存当前完整任务、命令意图、执行快照、事件和待同步项；分页、索引、冷热存储可以演进，但不改变长期留存语义。

对重叠任务采用事务锁定长者/机器及相关范围，配合适当数据库约束，并用并发集成测试证明只有一方成功。不要仅用页面禁用按钮或“先查再写”防重复。对补传、启动许可和删除等可重试操作，幂等范围须包含机构与实际对象身份。

契约生成的首轮探针至少覆盖：枚举、可空值、十进制字符串、日期/时区、版本冲突、错误响应、批量事件、旧字段兼容。生成代码能编译只是第一步，Dart 与 Python 对同一固定样例解释一致才算通过。

高质量的可读性，以及必要的精简

精简以读者需要理解多少概念、一次修改会触及多少位置衡量。保留必要的校验、持久化和异常分支；去掉重复规则、无价值转发层和提前搭建的通用框架。

代码应当这样呈现

  • 名称对应业务：领取任务、生成计划、恢复本批、确认人工结果。
  • 函数围绕一个意图组织，关键步骤顺序一眼可见。
  • 输入输出有明确类型；状态使用枚举或封闭类型。
  • 先处理非法输入与冲突，主流程保持平直。
  • 注释解释约束与原因，引用规则编号，不复述每行代码。
  • 错误保留上下文；用户文案和技术诊断分别面向各自读者。

控制复杂度的约束

  • 不为每个函数建立接口、工厂和服务三层。
  • 不让一个“通用管理器”拥有所有业务状态。
  • 相似代码先确认语义相同，再抽公共逻辑。
  • 不混用多套状态管理、数据库访问或 HTTP 方案。
  • 不用宽泛异常捕获后返回成功、空列表或零。

一个小函数应该清楚表达业务限制

下例是风格示意：表达当前常见整片/半片规则，不把设备容量、数据库或网络塞入同一函数；生产代码还需由完整计划校验检查能力、疗程和布局。

from decimal import Decimal
from enum import Enum

class FeedForm(Enum):
    WHOLE = "whole"
    HALF = "half"

def particle_count(dose: Decimal, form: FeedForm) -> int:
    """将原片剂量转为本批颗粒数；规则 R02。"""
    if not dose.is_finite() or dose < 0:
        raise ValueError("剂量必须是有限的非负数")
    if dose == 0:
        return 0
    if form is FeedForm.HALF and dose == Decimal("0.5"):
        return 1
    if form is FeedForm.WHOLE and dose == dose.to_integral_value():
        return int(dose)
    raise ValueError("剂量无法用当前投料形态表达")

日常评审标准

  1. 看得懂：只看入口、类型和核心函数，能说清当前任务、拥有的状态和异常出口。
  2. 改得动：修改时段配置或参数策略，不需要改页面、协议和数据库中的多份同义规则。
  3. 不越界：页面不算可执行矩阵，不访问数据库；设备适配不修改处方；同步重试不触发设备动作。
  4. 有证据：关键业务、事务和恢复行为有可运行验证。简单样式和字段转发无需堆积镜像测试。
  5. 没有多余结构：每个新增抽象和依赖能解释当前用途；无用代码、废弃分支和重复转换及时删除。

建议工具基线为 Dart 格式化、Flutter analyze/test，以及 Python 的 Ruff、一个类型检查器和 pytest。选择后统一配置；检查用于维护实际质量，不用机械行数限制迫使代码拆成难以阅读的碎片。

协作任务按“工作人员完成什么”命名，附规则、固定样例、公开入口和验证方式。多个工作线可以并行，但共享契约、生成配置和锁文件应有统一整合者；接口变化及时通知，最后以同一完整流程验收。

本地数据库是未上传事实的保存位置，不作为可随时清除的缓存。升级保留绑定、配置、任务与待传记录；存储迁移有版本和可验证恢复路径。不要通过卸载重装解决常规故障，也不以只替换程序文件宣称已完成数据库回退。

首发由开发者下载已签名 APK，手动安装到机构统一管理的平板；同一应用标识和签名用于后续升级，签名密钥由开发者妥善保管。升级安排在任务结束、取盒完成且本机空闲后，先验证数据与待传项保留。首发不要求自动更新或商店发布。发布资料包含版本、最低系统要求、接口兼容范围、完整性校验与已知限制；Windows 和 iOS 的分发在对应阶段确定。
