# Pillxai Dispenser Windows 首版

版本 0.2.1，2026-10-18，分支 `feat/pillxai-dispenser-NT`。这是可运行、可继续实机联调的 Windows 首版。界面移除绿色，使用中性灰背景与少量蓝色强调、保留圆角；Windows 窗口采用原生圆角，点击关闭直接退出，不驻留托盘，并关闭本应用拥有的后台进程。未绑定药盒的具体标识直接显示并可一键复制，RFID 显示保留前导零的完整 UID。工作台统一使用“药盒识别”：领取后请求开仓，放到轨道上后由后台摄像头或 RFID 自动核验，不展示摄像头画面；换盘复用该组件并重新核验。原主导航始终保留，设置在工作区内提供中文分类侧栏与分组列表：常规、摆药规则、药盒布局、设备连接、软件更新，无需通过返回按钮退出设置。应用主标志为圆角白底 PNG，只有圆角外部透明，字形内部白色仍不透明；Windows 小尺寸图标保留两个 L 之间的清晰白色间隔，文字标志裁去空白画布后按实际比例显示。08、09 的完整生产架构与验收路线仍是后续目标，安装包生成不代替生产验收。

0.2.1 增加设备中断处理面板，可选择串口尝试重连，核对机器仍保留原批次后继续，或选择“结束此次分药（不记录）”。结束需人员确认机器停稳及药盒、药物已妥善处理，删除本次中央和本机任务、结果、设备反馈、任务关联审计及诊断，不保留中止记录、不推进覆盖、不发送设备动作。中央暂不可用时保留删除阶段，重启后可重试；删除完成前不可继续或新开任务。已结束的历史任务不能经此入口删除。串口写入失败会释放失效端口并更新断联状态；重连只打开端口，不自动发送矩阵。

## 首次使用

0.2.0 改为以准备清单为中心的“今日工作”，住民目录与当前用药紧凑展示，计划按盘切换并显示药名规格及投料准备量，执行卡统一指向当前操作药物。记录支持全历史筛选、时间排序及一致导出，详情先展示实际结果和处理经过，技术信息按需展开。日常页面移除装饰性英文标题、协议参数及版本号；模拟模式、异常和待同步继续可见。机构设置未保存时离开会提示。摄像头识别模块按需加载。版本升级不改变应用标识或已有数据目录。

0.1.11 将品牌名统一为 Pillxai，产品显示名为 Pillxai Dispenser。页面、窗口、安装包名称和下载文件名称已更新，圆角图标沿用已确认版本。原便携目录及 `data/` 保留，应用标识与本机配置键不变；升级后启动文件名为 `Pillxai Dispenser.exe`。安装版的数据路径仍由原应用标识定位。

`release/` 提供 Windows x64 安装包与便携 ZIP。推荐先解压便携包，运行 `Pillxai Dispenser.exe`，保持 `resources/` 与 `portable.flag` 在旁边。数据库、执行记录、日志和 WebView 数据保存在旁边的 `data/`。不需要 Node 或 Rust，使用电脑已有的 WebView2；包内不安装该系统运行时。

1. 首次打开创建平台管理账号，没有默认密码。
2. 创建养老院，进入该院，在人员页面创建院内管理员。院内管理员创建工作人员，工作人员只进入自己的院。
3. 新增住民与处方，填写药名、规格、整片或半片、四时段剂量、餐食要求及生效日期。半片填 0.5，投料使用人工预切的半片颗粒。
4. 设置覆盖天数、漏摆后从当天或次日开始、时段行排列和分盘默认值。日常摆药自动沿用规则，无需逐次选择覆盖日期。
5. 先用模拟模式演练。选择住民、核对计划，点击“领取并开仓放盒”，模拟模式用“模拟放入本人的药盒”。真实模式在开仓后直接放盒，摄像头条码和已绑定 RFID 都自动进入同一核验，不需要手动扫码、选择来源或查看摄像头画面；失败可重试开仓或识别设备。
6. 开始逐药投料，需要时暂停恢复。整盘完成后换盘并确认，继续下一药的参数和数量；不先关仓。实际取盒并确认后，查看记录与导出。
7. 实机联调前在设置选择真实机器、设备名称及串口，连接 STM32，115200／8N1／无流控。使用 HC-06 时，先在 Windows 完成蓝牙配对，再选择该模块的出站虚拟 COM；本次电脑核查对应 COM7，其他电脑或重新配对后重新确认。连接成功表示端口已打开，收到有效反馈及实际动作须分别验证，详见 [设备传输约定](04-device-contract.md#现有传输方式)。每台电脑使用不同设备名称，共用中央服务地址和本院账号。新任务开始必须联网，已开始任务由本机继续并保存事件，联网后同步。

本包默认启动 `127.0.0.1:4310` 本机试用服务。每台电脑各自启动试用服务不会共享数据。多电脑共用院内数据需部署共同中央后端，再在登录页填入共同服务地址；机构权限由中央服务校验。

## 已实现

- 平台、院内管理员和工作人员账号、机构切换与权限校验，直接 ID 访问也检查数据归属。
- 住民、床位、多个 RFID 和处方维护；处方历史、参数版本和操作审计留存。出药参数按处方药物条目独立、不共享，半片改整片重置校准状态。
- 自动日期计算、统一周期、整片和半片颗粒换算、可配置时段行、睡前、餐食分盘开关与数量预览。
- 中央任务领取和启动许可，本机逐药执行、进度、暂停恢复、换盘、人工异常处理及取盒结束。页面重载保留执行状态，关闭窗口直接退出并清理本应用的后台进程；正在摆药时先请求暂停、保存进度，重开后核对现场。
- 本机 SQLite 状态与事件事务保存、待同步队列和重复上传去重。重启执行程序后，正在执行的任务进入现场核对。
- 历史分页、计划快照和实际结果区分、原始事件及脉宽导出。模拟任务明确标记，不推进真实摆药覆盖日期。数据不自动清理。
- A4、22×22 毫米、每页 96 位的批量 PDF 标签，支持跨页，中文字体随包分发。
- 下载图标与检查更新入口。尚未配置发布端点和签名密钥，目前显示未发布可用更新，不宣称更新发布已经打通。

STM32 发送顺序见 [设备约定](04-device-contract.md)：当前药转盘参数、舵机参数、矩阵；整盘完成开仓；换盘确认后再次参数、矩阵。达到目标数量本身不结算为机器完成，仍等待完成反馈。格子表示计划，累计计数不冒充逐格实测。摆药完成不等于住民已服药。

## 代码边界与构建

| 路径 | 责任 |
| --- | --- |
| `apps/web` | React 界面，调用公开 API 和本机语义命令 |
| `apps/api` | 中央身份、资料、计划、任务归属与记录，业务模块显式组合 |
| `packages/contracts` | TypeSpec 权威接口，生成 OpenAPI 和 TypeScript 类型 |
| `packages/dispensing-policy` | 不依赖界面、数据库和串口的计划计算 |
| `native/crates/machine-runtime` | 本机 SQLite、串口、执行状态和同步 |
| `apps/desktop/src-tauri` | Windows 外壳、窗口、单实例和子进程通信 |
| `tests`、`tooling` | 行为验证、契约生成、构建与打包 |

`pnpm check` 检查 TypeScript，`pnpm test` 执行业务和 HTTP 测试，`pnpm contracts:generate` 生成契约，`pnpm build:web` 构建前端，`pnpm build:windows` 完成验证、Rust release 编译、资源打包和 NSIS 构建，输出安装包、便携 ZIP 与 SHA256 摘要。

开发网页分别运行 `pnpm dev:api`、`pnpm dev:bridge` 与 `pnpm dev:web`。浏览器桥接仅用于开发，不随桌面生产外壳启用。

pnpm 与 Cargo 依赖已锁定。TypeScript 7 主工程与 TypeScript 6 契约生成器分开安装，避免编译器接口不兼容。Rust 工具链及缓存在 `.tools/`，Node 和 C++ 工具使用已有版本。不全局安装工具，不修改系统 PATH、注册表、驱动、固件和服务；构建脚本临时配置环境变量后恢复。
