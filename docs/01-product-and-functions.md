# Pillxai Dispenser 产品与功能

本文件定义产品提供的能力、资料输入和可见输出。计算与执行规则唯一见 [02](02-workflows-and-rules.md)，默认设置见 [00](00-scope-and-defaults.md)，页面操作见 [06](06-pages-and-interactions.md)。除注明用户确认外，具体交互与字段要求为本版设计基线。

## 用户要完成的工作

维护住民的用药安排，系统按已保存设置自动计算本次覆盖日期，核对计划并识别所属住民的药盒，由机器逐药摆放，处理必要的换盘和异常，再查询发生过什么。覆盖规则在设置里调整好后通常保持不变，日常无需逐次选择日期。机器摆好药不等于住民已经服药。

首版实现 Windows 客户端，产品设计同时考虑后续 Android、网页端和 iOS。各端共享同一业务语义，按平台实际能力提供功能；平台边界和演进要求唯一见 [00](00-scope-and-defaults.md)。首批规模和性能要求唯一见 [07](07-performance-and-delivery.md)。

## 术语

| 名称 | 含义 |
| --- | --- |
| 机构 | 养老院，数据与院内人员权限的归属 |
| 住民 | 用药安排及摆药任务的对象 |
| 药品 | 药物身份及规格、剂型、图片等资料；名称不是唯一身份 |
| 处方药物条目（用药条目） | 某位住民某种药的用量、时段、餐食关系和有效期间，拥有稳定身份；本文“每份处方独立参数”落实到每个药物条目 |
| 用药版本 | 修改前后可区分的用药安排 |
| 计划 | 本次具体日期、时段、药物、数量、盘用途与位置 |
| 任务 | 一位住民一次摆药工作，可包含多药、多盘 |
| 批次 | 一台机器执行一种药在一个盘上的计划 |
| 药盒、药盘 | 药盒是识别所属住民的实体，盘是承载本次药格的操作单元；软件只需记录盘序及用途，不另建实体盒号 |
| 覆盖 | 有依据确认已经摆好的用药日期时段，不是库存或服药记录 |
| 参数档案 | 每份处方中各药物条目各自拥有的出药设置与学习版本，与剂量分开记录，不跨处方共享 |

## 角色与权限

**用户已确认 Q08**：平台管理员创建养老院及其管理员；院内管理员创建工作人员；普通工作人员仅进入本院，平台管理员可切换机构。

| 能力 | 平台管理员 | 院内管理员 | 普通工作人员 |
| --- | --- | --- | --- |
| 创建机构、指定院内管理员 | 可以 | 不可以 | 不可以 |
| 进入机构 | 可切换目标机构 | 本院 | 本院 |
| 创建、停用员工及设置权限 | 在所选机构管理 | 本院 | 不可以 |
| 维护资料与处方 | 在所选机构 | 本院 | 由院内管理员授权 |
| 执行摆药、查看资料与结果、导出标签 | 在所选机构且本机归属匹配时 | 本院 | 默认具备 |
| 修改机构设置、设备绑定 | 在所选机构 | 本院 | 不可以 |
| 维护设备、管理处方出药参数、导出业务记录 | 在所选机构 | 本院 | 按权限授权 |

平台管理员切换机构用于管理资料和记录，不会把本机设备改绑到新机构。本机有未结束任务时保留执行入口及原机构上下文，不能通过机构切换操作另一机构的物理设备。改绑设备只在本机无任务时由管理员显式操作。

## 功能目录

### F01 机构与工作环境

登录后显示人员、当前机构、本机设备及连接状态。院内人员自动进入本院；平台管理员选择机构。所有列表、搜索、附件、导出和直接按编号访问遵守同一机构归属，保存规则见 03。

### F02 账号管理

输入账号、显示名称、初始密码、机构与权限，创建可登录账号；用户名全系统唯一。支持修改本人密码、管理员重置本院员工密码、停用及恢复账号。停用不删除操作历史。登录失败与网络失败分别提示；不通过界面退出清除设备任务。

### F03 住民资料

姓名必填，床位与照片可选，编号由系统生成并保持稳定。支持按姓名、床位搜索，编辑、离院停用及历史查询。床位规则见 B09；离院后不再生成新任务，已发生记录保留。

### F04 标签绑定

一个住民可绑定多个 RFID，标签可解绑及重新绑定；同一机构内同一有效标签只能归属一个住民。条码直接表示住民身份。保存本次识别来源和原始标识；一人多个盒子无需创建独立盒号。识别冲突按 R06。

### F05 标签 PDF

选择住民及每人份数，预览、导出可下载的 A4 标签 PDF。姓名、床位和可识别的住民条码为标签内容；22 × 22 毫米、每页 8 × 12 的兼容布局见 04。支持单人多份和多人批量。只报告文件生成与保存结果。

### F06 药品与处方

输入药名、规格、剂型/计量单位、图片、启用时段各次用量、餐食关系、开始日期，以及长期或有限疗程。药名、规格说明、单位、开始日期及至少一个正用量时段必填；图片可选。餐食关系明确选择饭前、饭后、随餐或无餐食限制，不由药名推断。有限疗程输入结束日期或持续天数，两者换算后必须一致。

保存产生新用药版本，支持修改、停止与恢复；不硬删除历史。剂量与颗粒转换见 R02，半片改整片触发 R14。药品资料可以院内复用，但每份处方的药物条目各自保存出药参数，不共享。同名条目以稳定身份区分。“保存修改”“停止”“恢复”作用于原条目；“新增药物”和复制为新条目产生新身份并独立学习。同一条目恢复时，药物、规格、形态不变可保留自身参数；多药处方的分组不合并条目身份或参数。

### F07 待摆清单

显示住民、已有覆盖、本次建议日期、待摆药种数、待处理原因及已占用机器。可搜索、刷新及主动提前准备。提醒计算见 R01；记录读取失败不能显示成“无人待摆”。

### F08 计划预览

按已保存设置自动计算并展示具体日历日期、时段位置、每格各药数量、逐药总颗数及原片等价量、盘用途、药物图片和来源版本。预览用于核对，不要求每次选择天数或覆盖起点；需要修改覆盖规则时进入设置，保存后重新生成未开始计划。餐食分盘仍有本次开关。生成规则见 R01–R04。

### F09 多机任务

本机默认使用绑定机器，为选中的住民领取任务；其他机器列表显示状态、住民和进度，不提供远程摆药控制。归属冲突、取消与不可转交边界见 R05。各台独立工作，不以院内一个全局“当前住民”控制全部机器。

### F10 识别与开始

支持先选住民核验药盒，以及放盒识别住民后进入计划。匹配结果、计划和机器就绪条件共同决定能否开始；规则见 R06–R08。

### F11 逐药执行

当前药物、规格、图片、整片/半片投料提示、累计进度、盘用途和下一步持续可见。每种药开始后机器自动定位与计数。正常投料无需再点完成；药物切换与换盘规则见 R08、R13。

### F12 暂停与异常处理

提供暂停、恢复、跳过、人工核对、人工补齐及结束当前工作。保留原反馈与人工处理来源。暂停续摆、计数错误、堵转与物理断开分别按 R09–R12，不能统一处理成“重新开始”。

### F13 结束与取盒

结果页区分机器完成、人工完成、未完成和待核实，取盒完成后机器才能就绪。任务结果、取盒状态和同步状态分别展示。正常取盒与人工确认入口见 R13。

### F14 设备连接与维护

显示本机绑定设备、连接位置、型号、能力与可得版本信息；支持发现、连接、断开、清药、复位及故障处理。设备能力见 04；非执行维护需空闲，执行中只允许当前异常流程要求的动作。

### F15 参数管理

查看具体处方药物条目的当前参数、来源与版本，提供手动调节、保存及学习开关；没有跨处方共享或复制学习参数的功能。权限与流程见角色表、R14 和 06。学习经验不更改处方用量，所有调整可关联到批次。

### F16 记录与导出

按本院住民、日期、药物、设备、操作人和结果筛选；从任务进入计划、批次、反馈、人工处理、参数及采样。支持带字段说明的业务数据和原始采样导出。长期留存、事实粒度和更正规则见 03；离线续摆见 R12。

### F17 安装与更新

一个安装入口及桌面入口，界面提供下载图标获取服务器最新兼容发布版本并自动更新。发现、下载、等待空闲、安装、重启及失败结果可见。流程见 R15，发布与交付要求见 07。

### F18 设置与支持

机构设置、终端设备连接、参数策略各自保存并标明生效范围。默认值唯一见 00。提供版本、连接状态、待同步记录数及诊断导出，常见问题给出工作人员可执行的下一步，不要求查看开发者控制台。
