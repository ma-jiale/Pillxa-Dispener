# Pillxa Dispenser 业务流程与规则

本文件是当前执行行为的定义。Q 编号表示用户确认来源，其余细则为可改进的设计基线；实现以完成用户工作与验证结果为依据，调整时直接修改相关规则与案例。默认值统一见 [00](00-scope-and-defaults.md)，设备报文见 [04](04-device-contract.md)，数据字段语义见 [03](03-data-and-records.md)。

## 从处方到结果

维护长者与处方 → 按设置自动生成覆盖周期并核对 → 本机领取任务 → 识别药盒 → 确认开始 → 逐药执行/换盘 → 记录结果 → 取盒结束。

执行记录随着动作持续保存，不等到最终取盒才第一次落盘。联网时同步，离线按 R12 继续当前任务。处方、计划、执行结果各有独立身份。

## R01 日期与覆盖

**用户已确认 Q01、Q02，按 2026-10-23 最新要求更新**：七列最多表示本次第 1–7 天；同一长者的药通常摆到同一天。开始摆药确认弹窗可选择本次分发天数，默认 7 天，限 1–7 天，不要求每次修改。系统结合已有覆盖、处方、摆药日和已保存起点规则自动计算本次起点，不逐次选择起点。允许提前准备；首次或漏摆的当天/次日起点在设置中切换；不向已摆好未服用的旧盒补加新药。

1. 从确认弹窗读取本次准备天数 D（1–7 天，默认 7 天），从机构设置读取起点规则，结合机构业务日期、已有覆盖自动计算本次起点 S，所有药共用日期坐标。本次天数不改写长期机构设置，D 及实际覆盖日期保存到本次计划快照。
2. 首次或旧覆盖已早于今天：按设置中的当天/次日起算，不累计过去漏掉的日期。若所有参与药物均尚未生效，则自动从最早生效日开始，可提前准备，无需手选未来日期。
3. 正常衔接：下一周期从已有完整周期结束日的次日开始，今天可提前准备。不同药物的历史覆盖不一致时显示“覆盖需核对”；不得默认为每种药各自从第一列填入。
4. 本次计划末日为 S + D - 1；每种药只在自身生效日期范围内生成数量。若所有药均为有限疗程且提前结束，裁去最后有用药日之后的空日期；中间无用药的日期保持原列位置。
5. 有限疗程包含首尾日，结束日 = 开始日 + 持续天数 - 1。长期处方明确无预定结束日，不用巨大天数。
6. 本次没有任何用药格则不建任务，说明无需摆药；提醒阈值不限制工作人员主动提前准备按规则算出的下一周期。
7. 提醒按有用药需求的条目判断：无覆盖或已漏摆立即提示；连续覆盖截止日为今天或之后时，剩余天数 = 截止日 - 今天 + 1，低于或等于阈值时提示。疗程已全部覆盖的条目无需提醒。
8. 覆盖来自成功批次所对应的计划范围或人工确认范围，来源分别标记。跳过与未知结果不产生已完成覆盖。无逐格反馈的部分批次不能按累计颗数推断完成了哪些格。
9. 未完成项留在原任务“待处理”中，提供现场核对与人工补齐；不自动新建“补药到旧盒”的任务。主动重建未来计划时，已覆盖或已占用的日期时段需排除或提示处理原任务。

起点、天数、提醒默认值见 B03、B04。本次天数可在确认弹窗调整并重新生成、校验未开始计划；起点规则和提醒等长期规则仍在设置中保存，不逐次修改起始日期。调整天数不改写已开始任务，也不重新开仓。计划明确记录日期，不以星期名称替代。

## R02 剂量与颗粒

**用户已确认 Q04**：半片由人工预切，机器按半片颗粒计数；常见每次半片，不扩展整半片混合投料。普通处方以后改整片仍支持。

| 输入 | 执行表达 |
| --- | --- |
| 整片投料、某时段 n 片，n 为正整数 | 该格 n 颗整片 |
| 半片投料、某时段 0.5 片 | 该格 1 颗半片 |
| 某时段用量 0 | 不摆该药，该位置为零 |
| 负数、无法用本批投料形态表达的用量、超出设备能力 | 指明具体条目，不执行截断或取整后的计划 |

同种药在本次所有启用时段使用一致的投料形态；不要求不同药也使用同一形态。每批总颗数等于该盘所有目标格之和，原片等价量另存。半片每格 1 颗、21 格合计 21 颗 = 10.5 原片。规格中的 mg 不直接当成机器颗数。

首版不实现混合整半片或一般拆片算法；遇到不支持输入在保存/预览处说明，而不是到机器执行时猜测。同名不同规格分别核对，不能覆盖同名条目。

## R03 分盘与位置

**用户已确认 Q01、Q03**：机构可调整早午晚位置，启用第四格睡前；餐食分盘可开关。

- 先生成本次实际参与的日期用药，再决定分盘。
- 开启：饭前一组；饭后、随餐、无餐食限制另一组。两组都有本次用药才分两盘；只有一组时只用一盘。
- 关闭：不按餐食关系拆盘，但保留处方餐食字段，各药仍进入各自用药时段。
- 两盘时先饭前盘、后其他餐食关系盘。用途写完整，不把第二盘上所有药都标为“饭后服用”。
- 日期列表示本次第几天；时段位置采用机构映射，再由设备适配转换成机器行列。
- 睡前是盘内时段，与餐食分盘是两个维度。关闭分盘不关闭睡前。
- 未用位置为零。布局、时段、分盘选择保存在计划快照；改机构设置不改变已开始任务和历史计划。

默认值见 B05、B06；实体方向与协议转换见 04，不直接将物理从上到下等同协议行 0 起。

## R04 生成计划与处方修改

生成时读取有效用药版本、机构配置、本机能力和已有安排。缺失或不支持的条目逐项提示；不能默默漏掉后显示完整成功。

| 时机 | 处理 |
| --- | --- |
| 预览中修改处方或布局 | 标记计划过期，重新生成后再确认 |
| 确认弹窗调整本次天数 | 按原自动起点重新生成、校验并保存未开始计划；期间禁用开始按钮，不重新领取或开仓，不改长期设置 |
| 已领取、未开始 | 联网重核版本；变化则在信息确认弹窗重新生成并核对，不下发旧矩阵 |
| 任一药物已开始 | 当前任务继续使用启动时完整快照；在线收到变更时提示，可选择结束并核对。不得悄悄替换当前或后续药物矩阵 |
| 已完成 | 新处方用于未来计划；历史结果及当时用量不改写 |

首次启动前，中央确认本机仍持有任务并记录进入启动阶段，本地保存完整任务、启动意图和所需资料，完成这两步后才允许第一次摆药命令。启动中同样不可被另一终端领取；任一步结果不明时先恢复核对，不自动释放。命令结果不明时该任务属于已开始且待核实，不能作为“未开始”释放重领。

处方停止不删除历史；未开始任务需重新校验。已开始任务离线不能保证收到新处方，保留当时依据与同步时间，不承诺实时处方传播。

## R05 领取与多机独立执行

**用户最新确认，2026-10-18**：通常一台终端固定一台机器；首发为 Android 平板直连 HC-06。同院共用数据，各机器分别处理不同长者。

1. 本机领取所选任务并绑定设备与人员。中央只允许一个有效归属，失败方显示谁已领取，不发送设备动作。
2. 同一长者同一用药日期时段的重叠安排不能通过重复点击创建第二份执行；暂停、断网和页面关闭都不释放归属。
3. 未发生启动动作的任务可以取消领取，在另一台终端重新领取。
4. 已开始的任务不转交另一台机器接力。暂停恢复、现场核对、人工处理或结束都在原任务保留记录。
5. 同一设备只能执行一个任务或一项维护；一台换盘、暂停、异常不阻塞其他台。
6. 不因超时或失联把已开始任务自动分配给别人。人员回到原机器处理现场并结束后再释放占用。

其他终端能查看同院任务状态及最后更新时间；无远程暂停、下发矩阵等跨机控制要求。

## R06 药盒识别

**用户已确认 Q06**：只需知道属于哪位长者，一人可多盒，不建立独立实体盒号。

**用户最新确认，2026-10-23**：首次放盒必须先让机器开仓。准备入口只保留待准备、提前准备；点击长者行的“开始摆药”打开信息确认弹窗，同时自动领取、保存本机任务并请求开仓，归属成功前不发送机器动作。弹窗等待下位机在本次识别会话中检测并上报药盒 ID，匹配所选长者后才允许点击弹窗“开始摆药”；确认后直接进入正在分药界面。日常操作统一称“药盒识别”，不增加识别来源选择、扫码输入或再次点击扫描，不新增或推定硬件协议字段。开仓失败保留已领取任务并提供重试，不启动识别；弹窗重绘、切换页面或重载不重复开仓。取消只对尚未发生启动动作的任务释放归属，现场未处理完成不能宣称本机已就绪。换盘采用同一识别组件，放好并核验下一盘后由人员确认继续。

| 输入 | 处理 |
| --- | --- |
| 条码/已绑定 RFID 匹配选中长者 | 显示匹配，可进入开始前核对 |
| 对应其他长者 | 提示不匹配，不自动换掉当前任务归属 |
| 自动识别长者无待摆需求 | 显示无需摆药，允许重新识别或查看资料 |
| RFID 未绑定 | 提示绑定或使用有效条码；不自动猜长者 |
| 两个有效来源指向不同长者 | 本次核验失效，要求重新核对 |
| 确认开始前取出或更换药盒 | 原核验失效，重新识别 |
| 摄像头不可用而 RFID 可用 | 继续自动识别，正常核验后不打断操作；识别仍失败时提供设备重试 |
| 两种识别均不可用 | 保留任务，修复识别后再开始 |

记录采用的来源、原始标识和归属，不把身份识别成功当成机械已到位。摄像头条码与 RFID 等来源各自记录观察；某来源无标识不抹掉另一来源的有效匹配，两个有效来源指向不同长者才判冲突。准备入口仍必须收到下位机本次检测的 ID 并匹配，其他来源观察不能替代该条件。开始前持续观察，标识更换、药盒取出或所有有效来源消失后核验失效，不能用上次缓存 ID 启用开始按钮；标签规范与兼容格式见 04。

## R07 状态与允许动作

| 阶段 | 进入依据 | 可用动作与离开条件 |
| --- | --- | --- |
| 待安排 | 已有有效计划 | 本机领取 → 待开始 |
| 待开始 | 本机领取成功 | 重生成、取消领取；完成识别与核对后开始 → 执行中 |
| 执行中 | 已保存启动意图并启动批次 | 暂停、当前参数调整、异常处理；同盘当前药正常完成后自动启动下一药，需换盘时等待核验与确认 |
| 等待人员处理 | 等待换盘或异常核对 | 确认换盘、完成核对；正常换药与投料无需点击开始或完成 |
| 已暂停 | 暂停获得确认 | 恢复同批次，或结束当前工作并核对已有量 |
| 执行中断 | 物理断开、系统强杀、异常重启或动作不明 | 重连并现场核对；按 R12 处理，不能重发未知批次 |
| 摆药处理结束 | 所有药均有完成、跳过或待核实的结果 | 开仓，进入取盒 |
| 已结束 | 已取盒，任务结果保存 | 查询、更正记录；不再次执行原矩阵 |
| 已取消 | 人员终止尚未执行的内容 | 一般保留已发生结果；R12 显式不记录例外按其删除流程处理，现场未处理完不得让设备就绪 |

状态之外分别保存业务结果（全部完成/部分完成/未完成/待核实）、设备状态和同步状态。已结束可以是部分完成；机器完成而待上传不等于摆药失败。请求已发送与已收到设备确认也分别显示。

## R08 逐药执行

**用户已确认 Q05**：开始后两个电机自动定位，工作人员可投药，机器自动计数，无投料完成按钮及逐格人工确认。

1. 首药显示药名、规格、图片、投料形态、盘用途及目标数量；点击“开始本药”启动本批次。
2. 下发参数与矩阵，显示准备/执行状态；进入设备适配所验证的可投料阶段后提示“可投入当前药物”。
3. 采集当前批次序号 N，显示 N / T；T 来自计划矩阵求和。重复或倒退序号不重复增加进度，原始反馈留存。
4. ACK 是接收确认；达到 T 是进度；FINISH 才是批次完成反馈。正常完成反馈与计数相符时保存机器完成；计数不符或反馈矛盾进入核对，不静默成功。
5. 按 2026-10-23 用户最新要求，同盘每药正常完成后自动切换并启动下一药，主内容、图片立即指向下一药，计数归零并加载该药开口值。进入设备适配确认的可投料阶段后，操作人员更换药物即可直接投料，不再点击“开始本药”或确认投料完成；主操作保持“暂停”。这不表示机器能够自动检测药物已更换。跨盘时仍按 R13 重新识别并确认换盘，确认后即启动下一药，不再另点一次开始。
6. 每盘完成后按 R13 换盘，全部药处理后汇总结果。

现有设备不回报逐格实测数量，不能由累计 N 反推每格实际落药。成功批次覆盖依据是计划加完成反馈；回收颗数不计入药盒数量。无序号批次身份的迟到消息处理边界见 04。

## R09 暂停与恢复

**用户已确认 Q05**：现有机器保留进度，恢复接着摆。

暂停保留任务、当前药、矩阵、计数及归属。恢复同批次，不重发完整矩阵、不新建任务。设备尚未确认则显示“暂停请求未确认”，允许检查连接。暂停不释放机器和长者任务给其他终端。

暂停续摆不意味着应用崩溃、断电或机器重启后可以无核对恢复，后者按 R12。

## R10 跳过与人工处理

**用户最新要求，2026-10-23**：正在分药页直接提供“跳过”。弹窗默认不勾选“将此药标记为已摆好”；不勾选确认则将当前药记为跳过，勾选表示人员已核对本次该药全部用量摆齐，保存独立人工确认结果，不改写机器累计计数。另设“跳过该长者所有剩余药物”，作用于当前药及尚未处理药，不改变既有完成结果，也不应用当前药的勾选状态。弹窗打开期间暂停当前执行，取消恢复原来的运行/暂停状态；跳过后原来运行则继续下一药，原来暂停则保持暂停。真实设备必须先完成下述退出流程才可切换，不能用弹窗消失代替设备确认。

任一药仅被跳过时不得将整个长者周期标为全部摆好；全部参与药物均正常完成或被人员明确标记已摆好后，才可形成完整覆盖。界面中的操作标签与真实结果来源分别保存。

| 操作 | 保存内容 | 覆盖 |
| --- | --- | --- |
| 跳过未完成 | 已有计数、未完成/未知范围、原因 | 不增加未知或未完成范围 |
| 人工补齐 | 日期时段范围、最终确认数量、操作人和时间 | 只确认该范围 |
| 计数异常核对 | 原错误、人工最终数量、更正关系 | 按核对结果 |
| 无法确定 | 已知报告、未知范围 | 标记待核实 |

先保存处理请求，再由适配器停转并退出当前批次。当前 STM32 适配依次等待停转 ACK、退出 ACK 和 DONE；退出确认前停留在等待阶段，不开放下一药。收到退出 DONE 后保存最终处理结果；最后一药结束则开仓取盒，即使本次结果仅部分完成。反馈未返回可转入现场核对，断线或重启也保留已知进度并转入核对，不自动重发退出或数量矩阵。部分已落药的情况不能一键“跳过即全部成功”。

正常完成不要求逐粒录入。人工已核对某药本盘全部按计划补齐时，可一次确认整个范围，来源必须是人工。这里处理当前任务的缺口，不增加给已完成旧盒追加新药的功能。

## R11 堵转与计数异常

异常面板显示机器、药物、错误与下一步。堵转可同时存在多个电机项，逐项清理和解除；解除一个不清除其他项。解除 ACK 不代表摆药完成。

计数异常进入现场核对，保存原反馈与人工结果。等待人员和设备运行时间分开统计；无须工作人员查看开发日志。维护动作及超时值由设备能力约定，不能把普通下载/查询超时套用到机械动作。

受控退出的停转与取消是两个阶段；彻底删除仅适用于人员另行明确选择的“结束此次分药（不记录）”入口，该断联入口仍不自动发送机器命令。划掉最近任务是否属于用户所说的“关掉软件”需确认；Android 系统强制停止、异常杀进程或断电不能保证应用有机会下发停转命令，必须列为异常中断并实测设备失联后的行为。后台正常运行也不等于可绕过下一药、换盘和现场核对所需的人员操作。

受控取消只针对尚未结束的本次任务。如果本次已完成的部分批次曾同步，中央须在同一取消事务中使本次全部覆盖失效，不影响其他任务历史。断网时本机持久化取消事实及待同步项，明确显示尚待中央确认；未完成现场处理不释放本机，中央不因失联自动重分配。重复同步取消不能重新执行机器动作或重复产生覆盖。

选择“结束此次分药（不记录）”是上述保留原任务规则的显式例外：人员确认停止投料、机器已安全停稳并妥善处理药盒和药物后，删除这次任务、结果及全部设备反馈，不保留中止记录，不计入完成覆盖。软件不代替人员确认停稳或取盒，不发送开仓、关仓或其他机器命令。先持久化本机删除意图并关闭串口，再删除中央任务及事件、任务关联审计，最后删除本机快照、同步队列及本次诊断数据。中央不可用时停留“正在结束并删除”，允许重试；重启仍保留该阶段，不能继续或新开任务。已结束历史任务不能通过此入口删除。

离线期间本机结果与采样持续保存，联网后只补传记录，不重做动作、不上传旧处方覆盖新处方。界面显示待同步数量，其他终端显示该机最后已知状态，不伪装成实时。同步精度与更正见 03。

## R13 换盘与取盒

**用户最新确认，2026-10-18**：每次换盘必须重新识别通过后才能继续。换盘显示长者、已完成盘、下一盘用途和日期。整盘完成后开仓，清除上一盘的核验结果；人员更换盘，本次新观察确认属于当前长者后，“已换好，继续”才可用。未识别、冲突或其他长者均阻止继续。确认后直接发送下一药的转盘、舵机参数，再发送数量矩阵，不发送关仓命令，也不增加一次开始点击；不要求另建实体盒号。

## R14 每份处方独立的出药参数

**用户已确认 Q10**：每份处方独立记录出药参数，不共享。同药、同规格、同整半片形态的不同处方也不互用学习结果；半片改整片后重新调整。

### 归属与延续

一份处方包含多种药时，每个药物条目分别保存参数，以稳定的处方药物条目标识关联，不以药名或药品资料标识关联。

- 同一长者的两份处方、同一处方的两个药物条目、不同长者的处方，参数都分别保存。
- 新建处方或新增药物条目从适用设备的默认参数开始，独立学习；复制处方资料不复制已学习参数，也不提供从其他处方导入参数的入口。
- 原条目的普通修改产生新用药版本，药物、规格、投料形态不变时可继续使用该条目自身的历史经验，不因保存版本就全部重学。
- 药物、规格或投料形态改变（包括半片改整片）时重新调整，旧参数留作历史，不继续作为新形态的当前学习值。
- 同一处方条目的后续任务可在适用范围内的另一台机器执行，并读取该条目自身参数；记录实际来源和使用设备。这是同一处方的数据同步，不是跨处方共享，也不允许已开始任务跨机接力。

### 学习与生效

批次开始时记录本条目参数版本及实际下发值。当前批次的手动调整记为本批实际设置；正常结束且满足策略条件时，学习结果仅更新该处方条目的参数。异常或样本不足不自动生成成功学习，但原采样与调整事件仍保存。

有权限的人员可显式保存本条目手动参数。新版本供该条目的后续批次使用，不改变已开始批次或任何其他处方。共用计算公式和设备初值不等于共享已学习结果。

### 保存与离线回传

更新关联处方条目、所依据参数版本、药物/规格/投料形态、来源批次或人员。中央版本和适用内容未变时保存为新的当前版本；同一更新重复上传不重复创建。

若基础版本或投料形态已变化，仍保存本批实际参数、采样和计算结果作为历史，不覆盖当前参数。界面提示“参数已变化，请刷新后重新调整”。离线回传使用同一规则，不用旧半片结果覆盖新的整片参数。

采样门槛、公式及来源见 04，历史与留存见 03。
