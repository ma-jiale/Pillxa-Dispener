# Pillxa 客户端交互预览

这是面向 Android 平板首发的 Flutter 客户端预览。当前采用用户确认的极简风格作为唯一界面，移除底部方案切换栏和其他方案，继续完善处方管理。浏览器预览用于快速评审，Android Debug APK 用于在平板上体验实际尺寸与触控。

本轮已建立界面和内存演示交互，尚未接入 FastAPI、HC-06、摄像头或 RFID、Android 后台生命周期和生产数据持久化。准备弹窗根据内存处方、本次天数和用药有效日期生成 GUI 计划与颗粒图案；执行进度仍由定时器模拟，不控制机器。这不是中央生产计划服务。

每种药完成后，下一药从预告卡片的实际位置移动并展开为当前药，原当前药退出，随后补入新的下一药预告；宽屏从右向左接替，窄屏从下向上接替，全程约 680 毫秒。计数和开口值重置后直接进入下一药的摆药状态，无需再点击“开始本药”，主操作保持“暂停”。最后一种药完成后结束本次演示并返回待摆清单。当前自动计数仍为定时器演示，没有药物更换检测或设备动作。

## 可以体验什么

左侧仅保留 `Pillxa` 文字字标，按“摆药”“处方管理”“设置”排列，登录后默认进入摆药，直接切换，不设返回页。当前侧栏按最新确认采用图标文字横排和较长圆角矩形；选中背景固定浅灰，不随强调色变化。设置使用齿轮、摆药使用下半黑色与上半白色的胶囊，处方管理保留原图标。三个页面共用当前演示状态。

| 模块 | 当前交互 |
| --- | --- |
| 处方管理 | 统一展示带彩色简笔画头像的长者，按姓名和床位搜索，新增及编辑资料；维护分时段剂量、餐食、投料形态和用药日期，停用与恢复药物条目 |
| 摆药 | 待准备/提前准备清单、默认 7 天的文字确认、独立药格图案；执行页支持暂停继续、自动切药、调整开口、跳过当前药并可人工标记已摆好，或跳过该长者全部剩余药物 |
| 设置 | 通用、外观、关于与跨分类搜索；关于提供版本、检查更新及自动更新开关；去掉本机设备、图片显示和重置演示入口 |

主体采用白色或浅灰背景，灰色区分层级。黑色是默认强调色，可在设置中更改；药品图片保留原色。设置变化仅用于交互体验，尚不参与生产计划计算。

摆药沿用处方管理原有的白色细边框卡片风格：`Surface` 统一白底、16 像素圆角、浅灰边框与标准留白。处方管理保留长者列表和资料、用药详情，移除整个“摆药准备”栏；准备与开始摆药统一从左侧“摆药”模块进入。摆药待准备/提前准备清单及执行中的当前药、下一药均复用同一容器，保留卡片接替动画和药品图片原色。

界面使用正常业务文案，移除演示说明、账号快捷填充与模拟操作选择器。左下角保留账户头像、院内管理员身份及退出操作；真实登录服务尚未接入。有执行中或暂停的任务时，须先完成或结束当前摆药。登录页和加载页仅显示 Pillxa 文字字标，移除品牌图像 Logo，Web 页签与应用清单也不再引用该图像；原素材保留为参考。

摆药、处方管理及执行页的主标题由工作区顶栏显示，正文不重复标题。移除页面说明小标题和待摆清单顶部日期。设置页标题仅放在左侧分类栏顶部，与主侧边栏、分类栏共用 `AppPage.navigationBackground` 浅灰色；右侧不设顶栏，白色分组内容区直接延伸到顶部。设置页采用左侧分类、右侧分组列表，提供通用、外观、关于三类；窄屏保留顶部标题，使用分类选择器。搜索跨分类筛选设置，切换分类保留未应用的颜色输入。不再展示“本机设备”分类、无法操作的“图片显示”整组说明或演示重置。设备管理统一从摆药界面右上角状态按钮进入。

“关于”展示当前版本、“检查更新”按钮与默认开启的“自动更新”开关，开关状态仅在本次会话保存。自动更新的目标行为是空闲时自动下载并安装，摆药期间不安装。当前仅实现 UI；点击检查更新提示“更新服务尚未接入”，不会显示“已是最新版本”，也不会下载或安装软件。

姓名必填、床位选填；所有已登记长者的非空床位不能重复。用药表单校验正剂量、整片/半片匹配、有效日期和睡前格设置，取消修改时保护未保存输入。修改处方不会改写已经创建的演示任务。图片上传、标签和历史版本持久化尚未实现。

2026-10-23 已接入新的待摆入口。王奶奶包含七药样例，李奶奶有会话内的模拟覆盖。确认弹窗不再伪造开仓或允许人员指定“本人药盒”，默认如实显示设备未连接并禁用开始；`boxFeedback` 为只读展示输入，测试在组件外注入状态，真实设备适配仍未实现。关闭图案保留天数和当前识别状态。计划颗粒按有效日期和半片换算；完整中央覆盖一致性、并发领取、餐食多盘及取盒仍待接入。

跳过弹窗默认不勾选“将此药标记为已摆好”。单药人工标记保存独立确认数量并保留原计数，批量跳过只作用于当前及剩余药物、不应用单药勾选。正常完成、人工标记与跳过分别保存在当前任务的内存结果中；存在跳过时不增加整个周期的完整覆盖。弹窗期间暂停，取消恢复打开前状态；真实停转/退出协议和结果持久化仍未接入，不能将 GUI 状态变化当成机器已执行。

图案“关闭”使用当前点缀色，移除左下角“计划·1点1颗”和姓名后的圆点；通过等宽空白保留原有日期起点。

## 登录预览

首次启动显示登录表单，登录后默认进入摆药。提供密码显隐、必填校验和普通错误提示，手机键盘弹出时仍可操作。默认管理员账号为 `admin`，密码为 `admin123`，需要手动输入；不提供快捷填充。登录后账户区和菜单显示“管理员 / 院内管理员”，替换原 `demo` 测试账号。仅提供本地 UI 登录，未实现账号管理或真实权限控制。此流程不代表真实认证、授权或安全会话已经实现，不发送、记录或持久化输入的密码。刷新或重启后重新登录。`initiallySignedIn` 只用于 GUI 测试构造已登录场景。

## 串口设备界面

仅摆药界面右上角用实物前脸提炼的摆药机矢量图标统一代表蓝牙与 USB 串口。图标在 `widgets/dispenser_icon.dart` 绘制，所有显示尺寸统一采用最初的简洁轮廓：圆角机壳、双观察孔、料斗弧线与底部托盘，不使用蓝牙图标。顶栏、列表与搜索图标分别为 22、38、48 像素。设备管理仅从摆药界面右上角状态按钮进入，处方管理和设置不显示该按钮，点击打开“我的设备”大面板，关闭后仍在原业务页面。

“我的设备”采用横向列表：左侧设备图标，中间名称及连接状态/方式，右侧连接、断开和移除；底部固定添加新设备。搜索在面板内部切换，顶部返回/关闭，中部开机、蓝牙靠近与 USB 插线提示，下方显示设备结果，底部重新搜索。保留当前白灰风格。

`DevicePreviewModel` 仅保存会话内设备列表和单连接状态。示例包含 PillDispenser01–03 和 USB 串口设备；没有调用真实扫描、配对、串口或 FastAPI。点击连接不改变药盒识别或启动许可。活跃任务禁止更改连接和移除，关闭/返回取消搜索，刷新后重置。真实 USB 与蓝牙权限、稳定身份、连接异常和后台恢复尚未实现。

使用 `flutter test --no-pub test/devices_test.dart --dart-define=UI_CAPTURE=devices` 在 `.tools/ui-review/` 生成设备面板截图，覆盖 1280×800、1024×600、390×844。已检查实际 Flutter 渲染的设备列表及搜索布局；Android 硬件未实测。2026-10-23 前轮设备图标调整后，静态检查、4 项设备界面测试及 Web 构建通过；删除处方管理的整栏摆药准备入口后，处方表单、三尺寸视觉和设备界面的 17 项相关测试与静态检查通过，Web 已重新构建。当前图标统一采用上述原简洁版定义。删除设置中的本机设备分类并加入更新控件后，16 项相关测试和静态检查通过，Web 预览已重新构建；真实更新服务未实现。

## 技术选择与官方参考

本轮研究了 [Flutter Material 3 组件](https://docs.flutter.dev/ui/widgets/material)、[Forui](https://forui.dev/) 和 [Shadcn UI for Flutter](https://mariuti.com/flutter-shadcn-ui/)。Forui 提供可定制的简约 Flutter 组件；Shadcn UI for Flutter 提供主题与组件，并说明了和 Material 组合使用的方式。

当前采用 **Material 3 + 小型自定义设计层**：使用现有按钮、输入、选择、弹窗和语义能力，以 `ThemeData` 和 `Surface` 集中定义间距、圆角、灰阶与边框，让三个模块保持一致并减少重叠的组件和主题依赖。Forui 和 Shadcn UI 本轮仅作研究参考，未加入依赖。

## 本地运行与构建

以下命令在**仓库根目录**的 PowerShell 中执行。项目当前使用 Flutter **3.47.1**、Dart **3.13.1**；依赖清单及锁定结果见 [pubspec.yaml](pubspec.yaml) 与 [pubspec.lock](pubspec.lock)。

统一入口 [scripts/flutter.cmd](../../scripts/flutter.cmd) 调用仓库内 `.tools/flutter`，自动切换到 `apps/client`。Pub、Gradle 和 Android 用户缓存均指向仓库 `.tools`；脚本仅配置当前进程，不改全局 PATH 或注册表。Android 构建使用本机已有 Android SDK 和 Android Studio JBR，可通过当前进程的 `ANDROID_SDK_ROOT`、`JAVA_HOME` 指定已有路径。

安装项目依赖、静态检查和测试：

```powershell
.\scripts\flutter.cmd pub get
.\scripts\flutter.cmd analyze
.\scripts\flutter.cmd test
```

构建并打开浏览器预览：

```powershell
.\scripts\flutter.cmd build web --release --no-web-resources-cdn
node .\scripts\serve-preview.cjs
```

服务启动后打开 [localhost:5180](http://localhost:5180/)；它只监听本机 `127.0.0.1:5180`，提供 `apps/client/build/web` 中的构建产物。修改代码后重新构建并刷新浏览器。结束预览服务可在对应终端按 `Ctrl+C`。

需要热重载时，可启动 Flutter 的开发预览：

```powershell
.\scripts\flutter.cmd run -d chrome
```

查看已连接终端、运行到指定设备，以及构建 Android 调试包：

```powershell
.\scripts\flutter.cmd devices
.\scripts\flutter.cmd run -d <device-id>
.\scripts\flutter.cmd build apk --debug
```

将 `<device-id>` 替换为设备列表中的实际 ID。Android Debug APK 输出为 [build/app/outputs/flutter-apk/app-debug.apk](build/app/outputs/flutter-apk/app-debug.apk)，可复制到 Android 平板手动安装体验。它是调试预览包，不是正式签名发布包。
